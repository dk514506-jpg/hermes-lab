## 4. WEAKNESSES

1. **MED — The "trend float-boundary fix" is mis-aimed and does not fix its
   own documented failure case** (phase11_intervention.py:191-194). The
   guard `if abs(delta) < min_change*0.01: delta = 0.0` snaps deltas near
   ZERO, not near ±min_change — the comment's own example ("-0.0499999 for
   a true -0.05") is untouched (0.0499999 is not < 0.0005, and
   -0.0499999 <= -0.05 is False → flat). Probe-confirmed misclassification:
   [0.65,0.7]→flat, [0.7,0.65]→flat, [0.1,0.15]→flat, [0.15,0.1]→flat —
   all exact 0.05 threshold moves — while [0.75,0.8]/[0.8,0.75] classify
   correctly (float error direction is input-dependent). Consequence: a true
   threshold fall reads as flat, and the W2 gate (`skill_load_trend !=
   "falling"` → ACT eligible, faos_ecology_engine.py:195) permits ACT while
   capability erodes exactly at the boundary. FIX: snap deltas within an
   epsilon of ±min_change to ±min_change (e.g. `if abs(abs(delta) -
   min_change) < 1e-9: delta = copysign(min_change, delta)`), and add
   boundary unit tests for under-approximating pairs.

2. **MED — select_bct does not implement the evidence-strength selection its
   own schema declares.** atomic_ops.json (select_bct, line ~294) and
   Phase11_Plan.md:57-58 say "Otherwise select by component-fit ×
   evidence-anchor strength"; the code (phase11_intervention.py:129-131)
   selects ALL non-reward candidates wholesale — fit_score/evidence_anchor
   are never read for any decision. Probe: a fit_score=0.10 candidate is
   selected alongside 0.99. The op degenerates to "Q7 filter + accept all."
   FIX: either implement threshold/rank selection on fit_score×anchor, or
   rewrite the schema description to "Q7-gated wholesale pass-through" (the
   honest option for a deterministic demo).

3. **MED — Confirmed-Q2 allowance is not wired into the merged engine.**
   FaosEcologyEngine.process_work_item (faos_ecology_engine.py:405-418)

   TwoTypedQuarantine (probe-confirmed). The DEFER→confirm path exists only
   on the standalone ConfirmedQuarantine class; through the engine API Q2 is
   hard-blocked and the allowance is inexpressible. FIX: add
   user_confirmed to process_work_item and use ConfirmedQuarantine in
   FaosEcologyEngine.__init__, or explicitly declare the allowance
   standalone-only in the plan/estate.
