## 1. The kernel (what is genuinely strong — specific packages/files)

- **COMB_Behavioral_Diagnosis is the exemplar.** Its 14 AtomicOps (atomic_ops.json) are a faithful, executable instantiation of the T2R COM-B row: `classify_component` is a six-label typed classifier with evidence-quote output; `ask_knowledge_probe` encodes guided discovery; the binding-constraint op exists (`identify_binding_constraint`, with an abstain-on-insufficient-evidence guardrail — the op the critique lens worried might be missing); and `label_hypothesis_status` + `record_diagnosis(user_corrections)` encode the hypothesis discipline *in the op graph*, not prose. Every op has inputs/outputs/guardrails; state_schema.json matches skill_node.json.
- **Proximal_Practice_Selector has the only *measurable* atrophy machinery**: `compute_skill_load` (0..1), `detect_atrophy_risk` (baseline-vs-recent arrays), `separate_performance_capability`, `fade_scaffolds` (evidence-tied, "fade is mandatory"), `readiness_gate`. This is a first-class metric with state variables, matching T2R's `skill_load_metric`/`readiness_gate` candidates.
- **Motivational_Lattice_Generator encodes hypothesis-status structurally**: `flag_identity_level_claim`, `quarantine_insight`, `record_user_verdict`, and a state_schema with `quarantine_status`, `user_verdict`, `manipulation_risk`, `surveillance_risk`. Best anti-paternalism design in the set.
- **MI got the three hard requirements right**: `spirit_gate` (hard gate), `track_commitment_slope` (Amrhein), `run_fidelity_gate` (0.84 ratio / ≥50% complex, coded not self-reported), plus `tag_change_talk` (DARN-CAT) and `plan_when_ready`.

## 2. The limitations (what is weak or wrong)

- **The flagship VERIFIED edge is uninstantiated.** `skill_graph_index.json` declares `decomposes_to COMB→TDF` ("VERIFIED (Cane 2012)"), but no package edge_map contains it. Worse, TDF's own map (edge_map.json) declares the *reverse*: `supports TDF→COMB` with the identical rationale. The two packages disagree on the direction of refinement, and both verifiers pass it.
- **Index/edge_map agreement is near-zero and the verifiers conceal it.** `_verify_skills.py` prints "PASS … 1 of 7 flagged edges match skill_graph_index.json" — a match counter, not a gate. Its comparison is direction-blind (`{source,target}` set equality), so reversed edges count as matches. `verify_packages.py` whitelists the deferred skills (`Material_Arrangement_Scan`, `Feedback_Ecology_Map`, `Autopoietic_Boundary_Check`, `Post_Close_Calibration_Debrief`, `Behavior_Definition_Cell`) in `KNOWN_SKILLS`, so edges to non-existent nodes pass as "resolved." Every package's map carries 5–10 such dangling `compatible_with` edges to skills that do not exist in the index (index lists them as deferred open items). Of the index's 8 edges, only ~5 appear in any package map (2 only modulo the id-case drift below); `decomposes_to COMB→TDF`, `recovers_with ConvoDojo→HEB`, and `supports HEB→*` are absent under canonical naming.
- **Typed edges are not coherent.** The same pair carries 2–3 edge types, often in both directions: SDT↔Proximal has `can_follow`+`supports`+`compatible_with` (both directions of `supports` exist — SDT map lines 92–101 vs Proximal map 203–208); ConvoDojo→HEB is simultaneously `can_follow`, `compatible_with`, and `recovers_with` (ConvoDojo edge_map lines 18, 22, 25); HEB↔COMB is `can_follow` (HEB map) but `recovers_with` (COMB map). Recovery ops (`Downgrade_To_Scaffold`, `Reopen_User_Choice`, …) appear as edge *sources* — the graph mixes skills, atomic ops, and recovery ops as nodes with no discriminator, so edge types have no defined node-kind domains. SDT's `can_follow SDT→HEB` (line 76) contradicts its own rationale ("boundary modes gate which utterances get audited" — semantically HEB→SDT).
- **Naming drift breaks composition.** Three names for one construct: `skill_load_metric` (T2R register, HEB prose), `skill_load_trend` (HEB state_schema, enum rising/flat/falling), `skill_load_score` (PPS state_schema, number 0..1). HEB's `assess_skill_atrophy_risk` reads `{skill_load_trend}`; PPS writes `skill_load_score` — no translation op exists, so the empowerment boundary cannot actually consume the one package that measures capability. `binding_constraint` collides: COMB's schema is the six-component enum, TDF's is `C|O|M|none` — same variable name, different domains, no namespace. Two skill ids per package: `ConvoDojo_Practice_Sparring`/`convo_dojo_practice_sparring`, `Motivational_Lattice_Generator`/`motivational_lattice_generator` (this alone hides index edges from the verifiers). `change_talk_log` is the one consistent spelling (MI writes, Lattice's observation_schema reads it) — the exception that proves the drift.
- **Two op schemas, enforced by two verifiers covering disjoint sets.** COMB/TDF/SDT/MI/PPS ops carry inputs/outputs/guardrails; HEB/MLG/ConvoDojo ops carry only template/description/arguments. `_verify_skills.py` explicitly excludes MLG/ConvoDojo for this; `verify_packages.py` covers only MLG/ConvoDojo/HEB. No tool validates the union.
- **ConvoDojo is the weakest package.** Zero guardrails on any op; the empowerment boundary is prose (SKILL.md) and edges only. Its theory instantiation is thin: practice-theory's `design_novelty_into_routine` (unfaithful repetition) and `detect_shared_elements` are absent; `sycophancy_risk`/`psychological_safety` state exists but no op reads it.
- **T2R register gaps (lens 1).** MI's Focusing process has no op — `focus_state` (agreed/unagreed) has no producer (`agree_direction`/`prioritize` absent). The entire BCW/BCT row (`canvass_full_range`, `select_bct`, `retrocode_delivered_plan`, bct_log) is uninstantiated by any package. Practice-theory materials/meanings/bundles (`scan_materials`, `detect_shared_elements`) and NPT/CMO (`assess_coherence`, `form_cmo_hypothesis`) are deferred with no package. `silence_decision` has no named op (HEB's `select_empowerment_mode` DEFER/STOP is partial). T2R op names are not traceable to package ids — no registry maps `autonomy_support_phrasing`→`suggest_autonomy_support_phrasing` or `skill_load_metric`→`compute_skill_load`.

## 3. The missing (what would raise it a level)

- A **single union schema** (one op schema, one node-kind enum: skill | atomic_op | recovery_op) enforced by one verifier over all 8 packages, with direction-sensitive, case-normalized index agreement as a *gate*, not a counter.
- **Edge semantics**: each edge type gets a defined node-kind domain and direction semantics; forbid duplicate pair/type multiplicity; derive per-package maps from the index (single source of truth) instead of mirroring by hand.
- A **T2R→package traceability registry** (register op id ↔ package op id ↔ state variable, with canonical namespaced state names) — kills the skill_load/binding_constraint collisions and makes the "did we instantiate the theory" question checkable.
- **Producer→consumer wiring**: an explicit `skill_load_score`→`skill_load_trend` conversion (or unified variable), plus Focusing ops, plus a stated decision on BCW/BCT (package or explicit scope exclusion).

## 5. Verdict

A strong theory-to-op core (COMB, PPS, Lattice, MI) wrapped in a graph layer whose edge typing, naming, and verification are too inconsistent to claim the packages compose — the seed index and the per-package maps are different graphs that the verifiers are currently engineered not to notice.
