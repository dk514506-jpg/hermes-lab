   clears the absence-register entry post_meld_live_llm_session"*.

   (config lines 413-418) and no human session occurred. I ran the script
   with the same args as the committed record: it wrote a record whose
   note contains neither phrase the verifier's honesty check requires,
   and verify_phase13.py then FAILED ("session: honest note ... 1 FAILURES").
   The committed record only passes because its note/run fields were
   corrected after generation — the shipped script, run as-is, produces
   a record the phase's own gate rejects, and claims a live session +
   absence-entry clearing that did not happen.
   *Fix: change run_dojo_session.py note to "platform wiring demonstration
   (Phase 13): deterministic machinery walk through the merged gateway ...;
   the genuine human-facing live LLM session remains the runtime act
   (absence register: human-session-pending)" and run to
   "phase13-platform-wiring-demonstration".*

   and declares victory.** Lines 103-112 only print stage ids and, where a

   metadata listings, not gate events. This is precisely the
   "list stages and declare victory" pattern the brief warned about.
   *Fix: minimally, implement guard evaluation — e.g. simulate a scenario
   where a guard's condition is true, show the HOLD and the retreat to
   retreat_target, and record the retreat in the record; or explicitly
   rename the field to `guards_catalogued` and demote the dissent pass to
   INCONCLUSIVE with "guard conditions not evaluated in this
   demonstration".*
