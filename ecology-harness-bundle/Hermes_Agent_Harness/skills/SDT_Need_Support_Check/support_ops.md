## Support Operations
Use these when prerequisites are missing before another skill can proceed — typically
when a user-facing flow lacks the need-support elements SDT requires.

### Offer_Choice_Menu
When a flow collapses the user's options, generate a real choice set (including
"or neither") with the trade-offs named — never a staged choice.

### Provide_NonControlling_Rationale
When an action must be done, supply the reason in informational form so the user can
endorse it volitionally instead of complying blindly.

### Provide_Informational_Feedback
When progress feedback is needed, frame it against the task and the user's own goals
(effectance), not as a verdict on the person. Informational feedback supports
competence; evaluative verdicts and controlling rewards undermine it.

### Suggest_Optimal_Challenge
When a task is too easy (boredom) or too hard (anxiety), calibrate the challenge one
step above current unassisted competence so success feels earned.

### Acknowledge_Perspective
When the user's frame conflicts with the agent's, restate the user's view before
offering any alternative — perspective-taking is an autonomy-support prerequisite for
MI evocation and for Feedback_Ecology_Map.

### Surface_User_Reasons
When the user's own reasons are invisible, elicit them (evocation) rather than
supplying the agent's reasons — the user's reasons are the raw material of
internalization.
