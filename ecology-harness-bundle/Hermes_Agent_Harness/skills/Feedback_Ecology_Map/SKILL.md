## Feedback Ecology Map

### Purpose
This skill applies the Normalization Process Theory lens (May & Finch
2009) to how a new routine embeds. A routine becomes normal through four
generative mechanisms: Coherence (sense-making), Cognitive Participation
(enrolment), Collective Action (operational work), and Reflexive
Monitoring (appraisal). This package maps where a routine sits on its
embedding trajectory, identifies the feedback loops that reinforce or
stall it, and forms Context-Mechanism-Outcome (CMO) hypotheses for
calibration — the embedding-work complement to COMB's diagnosis and
TDF's barrier grid.

Grounded in NPT as carried in the estate's Theory_to_Routine_Interface:
the four mechanisms (rows 64-67) and the governing rule "the user defines
meaning; the agent asks, never supplies" (row 64).

### Trigger Conditions
Use this skill when any of the following are true:
- The user is trying to make a new routine stick and it isn't yet normal
  ("it worked twice, then stopped").
- A practice has been started but its embedding is stalling — the NPT
  lens explains why.
- A COM-B diagnosis or TDF grid shows O-So/O-Ph feedback-loop evidence.
- The user asks why a routine that made sense still didn't take hold.
- Calibration needs a CMO hypothesis for what to adjust (and what NOT to
  touch — the user's meaning).

### Operation
1. assess_coherence — mechanism 1: "Does this routine make sense as part
   of your life?" (T2R rows 64/109). Outputs normalization_state[]:
   meaning, differentiation, internalization. The user defines meaning;
   the agent asks, never supplies.
2. form_cmo_hypothesis — realist-eval: Context-Mechanism-Outcome
   hypothesis for why embedding is or isn't taking hold. Hypotheses at
   claim level, never verdicts (Valens P4/P10).

### Boundaries
- The user defines meaning — the agent asks, never supplies (T2R row 64).
- CMO hypotheses are hypotheses, never verdicts; they feed calibration,
  never autonomous action.
- No embedding-work assessment pushes the user toward a routine they have
  not chosen.
- assess_participation / assess_collective_action / assess_monitoring
  (T2R rows 65-67) are REGISTERED-not-built: they read runtime signals
  the estate does not yet generate. Recorded, not deferred-blocked.
