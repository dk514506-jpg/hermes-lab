## 1. What is strong (with evidence)

**1.1 The README is a genuinely good orientation manual.** It answers the four
questions a fresh reader asks before touching a file: what this is (a
download-and-install package for a OneDrive/SharePoint estate, not a build
tree), what the required inventory is (table of 8 entries), how the layers
interconnect (lattice → skill graph → safeguards → dojos → evidence, with
logs/ as the feedback channel), and how to install or read it as a method
graph ("Consumers may install any subset; the graph index remains the source
of truth"). The governance section states the estate-scope rule ("estate
scope wins over package-local statements; conflicts are recorded, not
harmonized") and the verification gate. This is the single strongest
discoverability asset in the tree.

**1.2 Evidence discipline is threaded through every layer, not just the
evidence/ folder.** VERIFIED / RECONSTRUCTED flags appear on graph edges
(skill_graph_index.json edges carry `flag`), on lattice triggers
(lattice_index.json insight_triggers), on dojo grounding blocks
(Workplace_Dojo dialogue_state_machine.json `grounding` maps
EasyMED_2025/AgentForge_2026/Rudolph_2025/Ma_2025 to VERIFIED and
`dojo_design` to RECONSTRUCTED), and in the log contract
(logs/log_schema.md `evidence_flag` field). The "insights are hypotheses"
rule is stated in the index, the lattice index, the interface doc, the
trigger policy, and the log schema. The correction history is honest: the
index's edge notes record the COMB/TDF contradiction resolution verbatim
("TDF's contradictory supports TDF->COMB removed"), and handoff_notes.md
documents the critique round's fixes (README "all VERIFIED" claim corrected,
Jose 2025 opinion caveat, CALM-IT preprint flag).

**1.3 logs/log_schema.md is a real runtime contract, not a placeholder.**
Four event types (dojo_session, skill_load_snapshot, calibration_event,
boundary_gate_outcome) with required fields per type, a common envelope
(event_id, timestamp, session_id, source, schema_version, user_consent_ref,
evidence_flag), append-only semantics with correction-by-new-entry, consent
scoping ("logs are observations, never surveillance"), and a governance note
that logs never feed the persona module (Ma 2025). The scaffold ships empty
with .gitkeep — confirmed present. This is the layer that actually closes the
README's loop, and it is the best-specified runtime piece in the package.

**1.4 The skill packages are deep, self-consistent documents.**
ConvoDojo_Practice_Sparring/SKILL.md is a complete executor spec: 13
AtomicOps, the persona/coach separation invariant, anti-sycophancy as an
"orchestration invariant, not a style choice," 10 named failure modes, 8
recovery operations, and the lattice-interface rule that the persona is never
scripted from lattice insights. Human_Empowerment_Boundary/SKILL.md encodes
the five action modes (ACT/SCAFFOLD/ASK/DEFER/STOP) plus two genuinely
non-obvious Phase 5 additions — anti-empowerment-theater (Beacock 2026:
perceived agency ≠ structural empowerment) and friction-as-protective-design
(Xu 2026) — each with named VERIFIED anchors. The COMB edge_map's 14
decomposes_to ops each carry an evidence rationale (e.g., habit_scan:
"M-Au evidence from cue/routine/reward signals; flag habit-emotion
conflation"), which is exactly the right granularity for a method graph.

**1.5 Governance coherence is real where it matters most.** The HEB
boundary gate is declared on all 8 skill_nodes (verified in
ConvoDojo_Practice_Sparring/skill_node.json: governance.boundary_gate =
required, with the rule text) and in the index governance block. The
recovers_with cross-skill wiring (MI→SDT, ConvoDojo→HEB, COMB→HEB, TDF→HEB)
is consistent between the index and the interface doc. The dojo layer carries
concrete safety invariants: hard_gates in transition_policy
(no_personal_attack, power_gradient_guard, no_forced_commitment),
user_agreement.required on intensity, and psychological-safety-over-challenge
in every in_session_coaching_rules. The prediction-ceiling table
(insight_trigger_policy.md §3 — Shaikh 17-26%, Han 52.6%, Lim 0.80 LOOCV) is
an unusually disciplined way to keep low-confidence signals from licensing
autonomous action.

**1.6 Structural shape is exactly as claimed.** 8 skill packages × 9 core
files (verified by inventory), 5 dojos × exactly 7 artifacts, 4 evidence
files, 5 lattice artifact classes, logs scaffold, and the 8 required root
entries. The 5 dojos × 7 shape is enforced by verify_phase7.py (DOJO_7 list,
"no missing, no extra within a dojo dir"), and the dojo artifacts I sampled
conform to their declared schema (ecology-dojo/dialogue_state_machine/0.1).
handoff_notes.md is a strong continuity document — a fresh agent can re-enter
the campaign from disk, which is the stated purpose.

## 2. What is weak or missing (with specifics)

**2.1 Three of the five Phase 5 documents are not in the packaged tree,
despite the README claiming they ship inside it.** README.md (line 60-64)
states: "The Phase 5 estate controls (empowerment_boundary.md,
agent_deference_rules.md, learnability_state_schema.json,
skill_atrophy_risk_check.md, scaffolding_fade_rules.md) ship inside the
skills/Human_Empowerment_Boundary/ package and govern every layer below."
Only two of the five do. learnability_state_schema.json, skill_atrophy_risk_check.md
and scaffolding_fade_rules.md exist only at
../Phase5_Safeguards/ (outside the harness; confirmed). Meanwhile packaged
artifacts REQUIRE them: logs/log_schema.md's skill_load_snapshot event
mandates fields "per learnability_state_schema.json (ecology-learnability/0.1)"
and `fade_rung` "per scaffolding_fade_rules.md"; routines/README.md §2.4
cites "Phase5_Safeguards/scaffolding_fade_rules.md §3.5"; three dojos'
in_session_coaching_rules.md reference the fade policy. handoff_notes.md
confirms the intent ("safeguards stay in Foundation/ ... and bind the harness
via its README governance section") — but on a OneDrive/SharePoint estate,
the uploaded tree is what exists, and these cross-references are
unresolvable. The README's claim and the handoff's design contradict each
other, and both contradict the packaged content.

**2.2 The verifier is not shipped and does not check the consistency
classes it should.** verify_phase7.py lives in council_notes/, outside the
tree; README's "verified by council_notes/verify_phase7.py" and "not
uploaded until it exits 0" are not reproducible by a consumer of the
distribution copy. More importantly, the verifier passed a tree containing
every gap below: it checks inventory, JSON/YAML parse, index edge endpoints
against known node ids, and README section presence — but NOT edge-set
consistency between index and packages, quarantine flags inside packages,
stale path strings, presence of cross-referenced documents, or the T2R count
it could trivially assert. Every 2.x finding below is therefore unguarded at
the gate that is the harness's stated enforcement story.

**2.3 The "single source of truth" graph index is a curated subset, not the
full edge set.** Machine diff: 75 cross-skill edges in the eight package
edge_maps are absent from skill_graph_index.json's 10 edges (excluding
deferred targets and phantom nodes). Examples: ConvoDojo's can_follow
MI/SDT/HEB/MLG (present in ConvoDojo edge_map and SKILL.md, absent from the
index); COMB can_follow SDT/MI/PPS and supports PPS; TDF can_follow
SDT/MI/COMB; MLG's entire can_follow/compatible_with/supports set (which
exists only in lattice_index.json's lattice_skill_edges, not in the graph
index at all). The README's claim that "per-package edge_maps [were]
normalized to match" the index is not accurate as stated. There is even an
internal contradiction inside the index: the note on the COMB→TDF edge says
"only can_follow TDF->COMB reverse pass retained," and
skill_lattice_interface.md §4 lists TDF→COMB can_follow as a chaining rule —
but no such edge exists in the index's edges array (it exists only in
TDF's package edge_map). A consumer following the "source of truth" gets a
different graph than a consumer following the packages.

**2.4 Phantom nodes referenced as if they exist.** Post_Close_Calibration_Debrief
appears in 4 package edge_maps (HEB, MI, PPS — confirmed) plus 3 recovery_ops
files and 2 SKILL.md files, but it is in neither the index's built nodes nor
its deferred_nodes. Behavior_Definition_Cell appears in
Human_Empowerment_Boundary/SKILL.md's can_follow list but is absent from
HEB's own edge_map.json (intra-package contradiction) and from the index
entirely. Whether these are Phase 8 plans or leftover nodes, the index — the
declared source of truth — does not know they exist, so "deferred" status
cannot be reasoned about.

**2.5 Quarantine is expressed only in the index, not in the packages that
carry the edges.** COMB and TDF edge_maps list compatible_with
Material_Arrangement_Scan and Feedback_Ecology_Map as plain active edges with
no quarantine marker; the quarantine exists only in
skill_graph_index.json's quarantined_edges. A reader who opens a package (the
README's stated install path: "read the packages as the method graph") sees
dangling edges presented as live, with no indication they are quarantined
until a deferred skill is built.

**2.6 Stale distribution paths throughout.** Six SKILL.md handoff notes
point at Ecology/Foundation/Phase3_Skills/<package>/ (ConvoDojo, HEB, MLG,
MI, SDT, PPS — confirmed by grep), which is the pre-packaging location, not
the packaged skills/ location. routines/README.md §1 says the dojos "live
under Ecology/Foundation/Phase6_Dojo/<Dojo>_Dojo/" — wrong for this tree,
where they are at routines/<Dojo>_Dojo/. Two dojo dialogue_state_machine.json
files cite "source: Phase3_Skills/ConvoDojo_Practice_Sparring/...". And
ConvoDojo/SKILL.md's handoff says "Session logs and debriefs belong in the
harness routines/ folder," which directly contradicts the packaged
logs/log_schema.md contract that dojo_session events are written to logs/.
A fresh reader following these paths either finds nothing (Phase3_Skills,
Phase6_Dojo) or writes logs to the wrong place.

**2.7 Count drift between the index and the artifact it describes.**
skill_graph_index.json's open_items says "T2R_traceability.json: register-op
→ package-op traceability (47 entries...)". The actual file has 48 entries
(39 instantiated across variant statuses, 9 UNINSTANTIATED — README and
handoff both say 48/39/9 and are correct). Small, but it is exactly the class
of drift the verifier is positioned to catch and does not.

**2.8 Duplicated lattice schemas with nothing forcing identity.** The three
MLG schema files exist identically at lattices/ root AND inside
skills/Motivational_Lattice_Generator/ (diffed — byte-identical today).
lattice_index.json points at the package copies
("Motivational_Lattice_Generator/observation_schema.json"); the lattices/
root copies are therefore redundant, and verify_phase7.py tolerates ">= 1
present," so nothing prevents the copies from diverging later.

**2.9 Semantic oddity: self-edges in package edge maps.** Several packages
carry can_follow/supports edges whose target is the package's own skill id
(SDT can_follow SDT ×3, MI can_follow MI ×3, PPS supports PPS ×4 — machine
counted). These look like op-targets recorded against the skill id rather
than the op, or repeated-application chaining; either way they are
unreconciled, semantically confusing, and absent from the index.

## 3. Concrete improvement recommendations

**R1 — Ship the missing governance documents and make the README's claim
true.** Add learnability_state_schema.json, skill_atrophy_risk_check.md and
scaffolding_fade_rules.md into the harness (either inside the HEB package, as
the README already asserts, or in a top-level safeguards/ layer), and add a
verifier check that every file cross-referenced by a packaged artifact
(log_schema, routines README, in_session_coaching_rules) exists within the
tree. This is the highest-value fix: it converts the estate from "most of the
governance, plus references to the rest" to a self-contained package.

**R2 — Reconcile the graph index with the package edge maps, or relabel it.**
Pick one: (a) fold the ~75 missing package edges into
skill_graph_index.json with flags (large but honest), or (b) explicitly
declare the index a curated canonical subset, state the inclusion rule
(e.g., "index carries Phase 4 reconciled edges; package edge_maps carry the
full local set; package edges not in the index are package-scope by default"),
and fix the internal TDF→COMB contradiction (either add the edge or correct
the note and interface §4). Add a verifier check that diffs package edge_maps
against the index and fails on unclassified divergence. Do the same for the
lattice layer: MLG's edges should appear in one canonical place.

**R3 — Carry quarantine state into the packages.** Mark the deferred-target
edges in COMB/TDF edge_maps with an explicit "quarantined until
<node> built" flag (mirroring the index), or strip them from package edge_maps
and leave them index-only. Add a verifier check: any package edge targeting a
deferred node must carry a quarantine marker. And resolve the phantom nodes
(Behavior_Definition_Cell, Post_Close_Calibration_Debrief): add them to
deferred_nodes in the index with a reason, or delete the references — then
add a verifier check that every non-atomic-op edge target resolves to a
built or deferred node.

**R4 — Sweep the stale paths and the log-location contradiction.** Replace
Phase3_Skills/ and Phase6_Dojo references in the six SKILL.md handoff notes,
routines/README.md §1, and the two dialogue_state_machine.json source fields
with paths that resolve inside the packaged tree (or relative to it), and fix
ConvoDojo/SKILL.md's "session logs belong in routines/" to point at logs/ per
log_schema.md. Add a verifier check grepping for the stale path strings so
the sweep cannot regress. This is the cheapest discoverability win in the
package.

**R5 — Ship the verifier inside the tree and extend its scope.** Copy
verify_phase7.py into the harness (e.g., verify/verify_phase7.py, with
HARNESS_ROOT self-locating) so "exits 0" is reproducible on the estate, and
extend it to the check classes this review found unguarded: edge-set diff
(R2), quarantine markers (R3), phantom-node resolution (R3), stale path
strings (R4), cross-referenced-file presence (R1), the T2R entry count, and
identity of the duplicated lattice schemas (delete the redundant lattices/
root copies and assert the package copies are canonical).

---

## Verdict

Strong: the harness is a genuinely well-governed, deeply-specified method
graph — the README/handoff orientation, the evidence-discipline threading,
the log contract, the dojo safety invariants, and the boundary-gate
declaration are all above the bar for a download-and-install package, and
the structural inventory claims check out exactly.

Weak: the distribution copy is not yet self-contained (three governance
documents referenced but absent; verifier not shipped), and the declared
single source of truth (skill_graph_index.json) is inconsistent with the
package edge maps at scale (75 unindexed edges, one internally-contradicted
edge, two phantom nodes, unmarked quarantine in packages, stale install
paths, a count drift, and duplicated schemas). Every one of these is
mechanical to fix and mechanical to guard — none requires new research or new
policy, and all five recommendations are verifier-enforceable. The tree is
ready for Phase 8 evaluation work as a method graph; it should not be
uploaded to the estate in its current state under the claim that
verify_phase7.py's exit 0 covers consistency, because it does not.
