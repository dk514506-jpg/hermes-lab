## Support Operations
Use these when prerequisites are missing before another skill can proceed.

### Reopen_User_Choice
Name the decision that belongs to the user and provide options without deciding.

### Ask_Targeted_Clarification
Ask one precise question only when the action would otherwise collapse an underdetermined
high-meaning decision.

### Downgrade_To_Scaffold
Replace full execution with a template, checklist, partial draft, options list, or worked
example. (Canonical anti-overcompletion move; aligns with the obviousness-threshold
protocol — see obviousness_threshold_protocol.md.)

### Mark_As_Provisional
When using interpretation or motivational insight, explicitly mark it as hypothesis and
cite supporting evidence.

### Separate_Evidence_Interpretation_Implication
Rebuild a response into disciplined layers when overinterpretation risk appears.

### Obviousness_Threshold_Check
Apply the obviousness-threshold protocol (obviousness_threshold_protocol.md): act only
on what is genuinely obvious and reversible; anything ambiguous, high-branching, or
high-meaning moves to ASK/DEFER/SCAFFOLD. "Complete the obvious and no more."

### Option_Space_Preservation_Check
Run the option-space check (option_space_preservation_check.md): confirm the user's
choice set is at least as large after the action as before. If the action removes
options, downgrade the mode.

### Human_Decision_Point_Scan
Consult human_decision_point_detector.json: if the current state matches a protected
decision class (commitments, values, identity, meaning, stance, ambiguous branching,
interpretive closure), the action may not proceed past SCAFFOLD/ASK without user authority.

### Capability_Trajectory_Read
Read the skill_load_metric trend before any automation or assistance expansion. A
falling trend is a red flag that overrides performance/engagement gains (Bastani 2025,
Beacock 2026).
