## Support Operations
Use these when prerequisites are missing before another skill can proceed.

### Build_Scaffold_Levels
When no scaffold exists for a skill-building task, define 0–5 levels (5 = full
worked example, 4 = template with gaps, 3 = hint chain, 2 = single hint, 1 = check
after attempt, 0 = none) so fade decisions have a concrete ladder to move on.

### Provide_Hint_Bank
When minimal_sufficiency selects hint mode but no hints exist, generate a hint chain
ordered from least to most revealing — the answer itself is never level 1.

### Schedule_Fade_Review
When a scaffold is created, attach a fade review condition (next N unassisted
attempts, not a calendar date alone) so fade is evidence-tied by default.

### Collect_Readiness_Signals
When readiness is unknown, gather behavioral and stated signals (initiation timing,
self-reported readiness, change-talk from MI layer) before any proactive intervention.

### Explain_Skill_Load
When the user asks about their progress, render skill_load_score and the
unassisted track in plain language with no verdict framing — transparency about
capability, not surveillance.
