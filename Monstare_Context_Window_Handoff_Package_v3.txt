## 5.1  Orchestration model

The harness is a **coordinated batch of leaf subagents**, each bound to one role, plus a
**main Hermes session (Pip)** that owns orchestration, prioritization, synthesis, decision-
making, and delivery. The roles are not independent agents with their own conversations;
they are delegates spawned on demand by Pip, each given a bounded task, a role prompt, a
token budget, and a return format. Pip reconciles their outputs.

```
  Pip (main session, orchestrator)
   ├── Locus        (frame-keeper, QC steward, interface auditor)
   ├── Evidence Librarian   (source identity, access-path quality, source-status caveats,
   │                         source-checked dates; supports charting by confirming source
   │                         identity before claims are extracted)
   ├── Methodologist        (causal status, evidence type, limitations, effect-size claims,
   │                         SCED/pilot logic; prevents false generalization from N-of-1 or
   │                         weak/correlational papers)
   ├── Cosmotechnic-Purist  (guards against false cosmotechnics, veneer, nostalgia,
   │                         localism, and productivity optimization in cosmotechnic language)
   ├── Phenomenologist      (protects lived-experience fidelity, order-of-capture, and the
   │                         non-rational remainder)
   ├── Ethics & Cosmotechnic Auditor  (owns cross-stake collisions and protected-floor breaches)
   └── Data & Instrumentation Steward  (workbook usability, source-link fields, reversibility,
       anti-overload constraints; ensures future edits are additive patches only unless user
       explicitly authorizes restructuring)
```

## 5.2  When to build the full harness vs. a collapsed version

Build the full harness only when the charting batch is large enough to justify the overhead
and when the sources are diverse enough that role specialization catches things a single
reader would miss. Use the decision table:

| Condition | Action |
|---|---|
| Charting batch ≤ 4 rows, all from one area, all readable PDFs | Collapse to Pip + Locus only. Pip reads, charts, and runs the Locus check against its own output. |
| Batch 5-8 rows, mixed areas or mixed access types | Build Pip + Locus + Evidence Librarian + Methodologist. Spawn the other roles only if a specific concern arises (e.g. cosmotechnic claim → Cosmotechnic-Purist). |
| Batch 9-12 rows, or any batch touching a protected-floor stake | Build the full harness. Every role except Phenomenologist is spawned for the batch. Phenomenologist is spawned only when a row has a phenomenological capture dimension (A5, A9, ritual rows). |
| Token budget for the session is below the per-batch floor (see 5.4) | Defer the batch. Do not run a batch that cannot afford its QC layer. A charted row without QC is worse than an uncharted row. |
| A role's subagent returns unusable output (off-topic, truncated, hallucinated) | Mark the row as "QC failed — re-chart required," do not patch over it, and log the failure in the Source Patch Log under a new "QC failures" note. |

## 5.3  Role prompts and return contracts

Each role is spawned via `delegate_task` with a self-contained prompt. The prompt must
carry: (a) the role's mandate, (b) the specific rows or claims it is responsible for, (c)
the evidence matrix columns or claims it should examine, (d) the return format, and (e) the
token budget. Do not rely on the subagent remembering anything from the parent session —
pass the needed context inline.

The canonical role prompts live in this package's `references/role-prompts/` directory
(added by the next chat window when it builds the harness). The prompts below are the
minimum viable version; refine them after the first batch and save the refined versions
as the canonical prompts.

### 5.3.1  Pip (main session — NOT a subagent)

Pip is the parent session. Pip does not get spawned. Pip's responsibilities:
- Decompose the charting batch into per-row tasks.
- Decide which roles to spawn for the batch per the decision table in 5.2.
- Spawn each role with its prompt, budget, and context.
- Collect role outputs, reconcile contradictions, and populate the matrix columns.
- Run the batch-level Locus check (see 5.5) after all roles return.
- Produce the findings/fault-lines memo and the next handoff note.
- Maintain the token budget across the whole batch (see 5.4).

## 5.4  Cost-control measures (NEW IN v3)

The orchestration has a real token cost. Without explicit controls, a 12-row batch with a
full 7-role QC layer can burn through a session budget in one pass. The following measures
are mandatory, not advisory.

### 5.4.1  Per-session budget envelope

- Set a session token budget before starting. The recommended default for a charting session
  is 100,000 tokens total (input + output combined). Adjust upward only if the user explicitly
  authorizes it.
- Track spend as you go. After each batch, record actual spend in the handoff note.
- If spend reaches 80% of the session budget, stop spawning new roles and finish the current
  batch with Pip + Locus only. If spend reaches 95%, stop entirely and write the handoff note
  with the session's partial progress.

### 5.4.2  Per-role token budgets

Each role spawn carries its own budget. The budgets below are defaults; adjust per batch size
and source complexity. Do not exceed them without a deliberate decision recorded in the handoff
note.

| Role | Default budget per batch | When to increase | When to decrease |
|---|---|---|---|
| Locus | 8,000 tokens | Batch touches a protected-floor stake or a cosmotechnic claim | Single-area batch ≤ 4 rows |
| Evidence Librarian | 12,000 tokens | Row has a restricted/gated/landing-only source that needs identity confirmation | All rows are open PDFs with clear DOIs |
| Methodologist | 10,000 tokens | Row is load-bearing (Priority A) and empirical | Priority C rows |
| Cosmotechnic-Purist | 10,000 tokens | Row has Cosmo Rel. = high and a Cosmotechnic Implication | Cosmo Rel. = low rows |
| Phenomenologist | 8,000 tokens | Batch includes Area 5 / Area 8 / arousal-flow rows | Batch has no phenomenological rows |
| Ethics & Cosmotechnic Auditor | 8,000 tokens | Batch touches S1/S7/S10 or a Fail Mode | Batch is all Priority C |
| Data & Instrumentation Steward | 4,000 tokens | Any batch that writes matrix edits | N/A — this role is cheap and always worth it |

### 5.4.3  Batch-size discipline

- Batch size is 8-12 rows max, per the handoff. Do not exceed this.
- For each row in the batch, the total cost is approximately:
  (source access cost) + (Pip read + chart cost) + (role spawn costs for the roles active on
  that batch).
- If a batch's estimated cost exceeds 15% of the session budget, split it into two smaller
  batches.
- Priority A rows get the full QC layer. Priority B rows get Pip + Locus + Methodologist at
  minimum. Priority C rows get Pip + Locus only unless a specific concern arises.

### 5.4.4  Source access cost control

- Do not download full PDFs for every row. For most rows, reading the abstract, introduction,
  conclusion, and methods/results (if empirical) is enough for charting. Use web_extract or a
  targeted read, not a full PDF pull, unless the row is load-bearing and the source is short.
- For open PDFs under 30 pages, a full read is acceptable if the budget allows.
- For restricted/gated sources, do not burn budget trying to bypass the gate. Record the
  caveat and move on. Return to it only if the user provides access or explicitly prioritizes
  the row.
- For fast-moving AI/digital/work-trend rows (6-month re-search interval), prefer the most
  recent available source and record the access date. Do not chase multiple versions in one
  batch.

### 5.4.5  Role-collapse economy

The full 7-role harness is the expensive case. The economy comes from collapsing roles when
the batch doesn't need them. The decision table in 5.2 is the control. Do not spawn a role
"just in case." Spawn a role because the batch condition in 5.2 says to.

If after spawning you find that a role's output is low-signal (e.g. the Cosmotechnic-Purist
returns "none" across all fields for a batch of non-cosmotechnic rows), record that in the
handoff note and consider collapsing that role for the next batch of similar rows.

### 5.4.6  Model-tier guidance

- Pip (main session) should run on the default session model.
- Role subagents should run on the same model family unless a role explicitly benefits from a
  different tier. Do not mix models inside a single batch unless there is a documented reason
  (e.g. Methodologist on a reasoning-heavy model for empirical rows, Cosmotechnic-Purist on a
  model with strong philosophical comprehension).
- If the session model is a lower-tier model, increase the per-role budget slightly to compensate
  for the extra turns a weaker model may need to produce usable structured output.
- Do not use a more expensive model for a collapsed (Pip + Locus only) batch — that is the
  economy case, and a stronger model doe not substitute for the missing QC roles.

### 5.4.7  Hard stop conditions

Stop the charting session immediately if any of these occur:
1. A protected-floor breach is detected by the Ethics & Cosmotechnic Auditor and cannot be
   resolved by revising the matrix implication. Escalate to the user rather than patching over
   it.
2. The session token budget is exhausted (95% reached).
3. Two consecutive batches produce QC failures (rows marked "re-chart required") without a clear
   fix. Pause and diagnose before continuing.
4. The Data & Instrumentation Steward flags a proposed edit as forbidden and the user does not
   authorize it.
